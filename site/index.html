Then agents write and review, and stop at a gate.

Every step is a durable Temporal workflow, so a restart or a week of waiting loses nothing. A reviewer on another model than the writer judges each document; loops are bounded, and when the rounds run out a person is asked.

At a gate you approve, ask for changes with a note the agents receive, or stop the work. The primary action stands alone.

Last, a pull request, with the whole story on it.

It opens as a draft after the first step, carries one stage label and one progress comment that tells the run at a glance, and is ready for review only when the code has been reviewed. Reply /shelf approve on the pull request if you prefer GitHub to the web page.

Agents never merge. The merge is yours.

The pull request is never merged without you, and the code review and the repository's checks always run. Fewer stops mean more autonomy, less control and potentially less quality: the form says so.

A guard between the agent and your machine.

Warden, a small Rust program, judges every command, file access and fetch before an agent runs it. It refuses what the profile refuses, turns secrets and personal data in the output into tokens, and writes every decision to a log that cannot be changed unnoticed. Pick a command and a profile. The answers are the real output of warden explain.

Warden reads text. A program an agent writes and then runs is not seen inside, so the container, the sandbox and an allowlist stay the perimeter, and per-agent isolation is still to come. Limits says what it does not cover, and the guard page how to tune it.

Each repository keeps its own rules.

One file in the repository says what to run for checks, how many rounds a loop gets and who may decide where. It changes through a pull request, like any other rule.

Roles decide where.

The spec gate belongs to product_owner, the design review to architect and tech_lead, the pull request to tech_lead and developer. Administrators, listed by the operator in shelf.toml, may always decide. There is no user database: access is that file plus GitHub, closed by default.

Give agents your corporate skills.

The operator pins skills and plugins from git repositories to a full commit, and binds them to roles such as implementer or code_reviewer. A change is a change you review.

New. The lasting results of a run go where the repository keeps them: requirements in openspec/, decision records in docs/adr/, checked against the earlier ones, and a run's own files in .shelf/<work-id>/. Set it in the [results] section below.

# .shelf/config.toml, in the repository
base_branch = "main"
checks = ["make test"]            # what the checks step runs

[policy]
max_rounds = 3                    # how often a loop may send work back before a person is asked
spec_approval = true
design_review = true
proceed_on_deadlock = false

[roles]                           # leave out [roles] and any signed-in person may decide
product_owner = ["maria"]         # the spec gate
architect     = ["bob"]           # the design review
tech_lead     = ["bob", "carol"]  # the pull request
developer     = ["dan"]

[results]                         # where a run puts its specs and decision records
specs = "openspec/specs"
decisions = "docs/adr"
conflicts = "block"            # refuse a record that contradicts an earlier one

One server, one command.

$ git clone https://github.com/bhoudebert/shelf-sdlc-agents
$ cd shelf-sdlc-agents
$ sh deploy/install.sh https://shelf.example.org

Open that address. The first visit registers the GitHub App in one click and shows what to paste into deploy/.env. Run the script again, install the App on your repositories, sign in. A full walk-through is in Get started.

Get started

What it needs

  • A server with Docker and Docker Compose v2. The file starts Temporal, the web app (port 8080) and the worker.
  • A public HTTPS address in front of port 8080, from any reverse proxy or tunnel. None is bundled.
  • A GitHub App. The first page registers it for you with the right permissions and events.
  • A model credential: an Anthropic API key, a Claude subscription token or a compatible gateway.

What it costs

Shelf itself is free, Apache-2.0. You pay for the server, and for the model your credential uses, at that provider's rates. A run takes more rounds and more tokens than asking one agent directly, because reviewers read cold; that is the price of the review. You bound it: SHELF_MAX_TURNS (40 by default) and an optional SHELF_MAX_BUDGET_USD per step, and the worker logs the cost of each step. A total per work item is not built yet.
