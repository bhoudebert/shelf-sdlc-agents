One work item, one durable workflow.

Every piece of work is a Temporal workflow, so it survives restarts and can wait days for a person.

  1. Sign in

    One GitHub App handles sign-in, repository access and the agents' identity. You choose a repository you granted to it.

  2. Start anywhere

    From the web UI, pick the step to begin at and describe the work.

  3. Agents work

    Each step runs on the Claude Agent SDK in a fresh clone of the repository.

  4. People decide

    At a gate you approve, request changes, resume, reject or abort, from the UI or on the pull request.

Built to be trusted with your repository.

Agents propose. The rules around them are fixed, small and checkable.

Loops are bounded

When a reviewer asks for changes or checks fail, the work retries a fixed number of rounds, then escalates to a person. Nothing spins forever.

People hold the gates

Decisions come from a closed list of commands (approve, request changes, resume, reject, abort). A model never interprets them.

Durable by design

State lives in Temporal. A worker restart, a deploy or a week of silence does not lose the work item.

A pure core

The rules are one function, decide(state, event) -> (state, commands). The workflow only interprets it, so the logic is testable with plain properties.

Self-host in minutes.

One docker compose file runs Temporal, the web app and the worker. There is no bundled reverse proxy: put any TLS proxy in front, or use a Kubernetes ingress.

  1. Run sh deploy/install.sh https://your-address.
  2. Open the address: one click registers the GitHub App and shows what to paste into deploy/.env, with a model key.
  3. Run the script again, install the App on your repositories, sign in.
Read the guide
$ git clone https://github.com/bhoudebert/shelf-sdlc-agents
$ cd shelf-sdlc-agents
$ sh deploy/install.sh https://shelf.example.com

# deploy/.env  (written for you)
PUBLIC_URL=https://shelf.example.com
SESSION_SECRET=...        # generated
ANTHROPIC_API_KEY=sk-ant-...
GITHUB_APP_ID=...         # pasted after the one-click registration

The stack boots on real Docker: Temporal healthy, the web service answering, the worker waiting for the App. A full run with a real model is the next checkpoint.

Status and roadmap, honestly.

shelf-sdlc is in early development. Every piece is built and tested; a full run with a real model on a real repository is not verified yet.

Built and tested

  • The pure work-item state machine, with property tests
  • Access rules, roles, ports and the use cases
  • The Temporal workflow, tested on a real server with history replay
  • The GitHub App adapter: sign-in, repositories, installation tokens, pull requests, one-click registration
  • The step runner: a fresh clone per step, role prompts, verdicts, the project's checks
  • The web interface, with a live board and decisions
  • The Docker Compose deployment, booted on real Docker

Next

  • A first full run with a real model
  • Per-repository settings in the interface
  • Very long waits (continue-as-new)
  • Another agent backend

Follow progress and contribute in the repository. Read the architecture and the security model to see where it is heading.
