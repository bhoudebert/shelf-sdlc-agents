Get started

One server, one command, one GitHub App, one model credential.

Early development. The stack boots and is tested on real Docker. A full run with a real model on a real repository has not been verified yet, so expect rough edges and tell us about them. Start with the guard in observe mode.

What you need

  • A server with Docker and Docker Compose v2. The compose file starts three services: Temporal (data on a volume), web (sign-in, the interface, webhooks; port 8080) and worker (runs the workflows and the agents; scale it with --scale worker=3).
  • A public HTTPS address for the instance, because GitHub redirects people and sends webhooks to it. No reverse proxy is bundled: terminate TLS with one you have, a tunnel or an ingress, and point it at the web service. No Kubernetes manifests are provided; deploy/compose.yml lists every service, variable and volume.
  • A GitHub account that can create a GitHub App. The app is free, and the first page registers it for you.
  • A model credential: an Anthropic API key, a Claude subscription token (claude setup-token), or an Anthropic-compatible gateway.

What it costs

Shelf is free software (Apache-2.0); there is no licence fee and no hosted service. You pay for the server and for the model your credential uses, at that provider's rates. Every step is bounded by turns (SHELF_MAX_TURNS, 40 by default) and, if you set it, by dollars (SHELF_MAX_BUDGET_USD), and the worker logs what each step cost. A total per work item and a view of it are not built yet (roadmap). A run uses more rounds and tokens than asking one agent directly: that is the cost of having every document reviewed.

Install

git clone https://github.com/bhoudebert/shelf-sdlc-agents
cd shelf-sdlc-agents
sh deploy/install.sh https://shelf.example.org

This writes deploy/.env with a generated session secret and starts the stack. The script checks the usual mistakes first (Docker present, the port free, an empty PUBLIC_URL). Add your model credential to the file (ANTHROPIC_API_KEY or CLAUDE_CODE_OAUTH_TOKEN).

The first sign-in

  1. Say who may sign in. The script created deploy/config/shelf.toml from shelf.toml.example. It is yours and git ignores it. Name yourself under users and admins, or an organisation under orgs. With all three lists empty nobody can sign in, you included: access is closed by default. 
    mode = "server"

[access]
users  = ["alice"]
admins = ["alice"]
  2. Register the GitHub App. Open your address. While no App is configured, the first page offers one click to register it with the right permissions and events, then shows the credentials once. Paste them into deploy/.env and put the key at deploy/secrets/github-app.pem. The GitHub App has every value and what to do when it goes wrong.
  3. Run the script again so the stack restarts with the App: sh deploy/install.sh.
  4. Install the App on the repositories you want (the board links to it), and sign in.
  5. Check that the agents work.
    docker compose -f deploy/compose.yml exec worker shelf-doctor
    It asks real, tiny agent tasks in a throwaway repository (a shell, the repository's CLAUDE.md, the pull request title convention, commands in the sandbox, the credential) and tells you what to do about each failure.

Start the guard in observe mode. Add SHELF_WARDEN_PROFILE=observe to deploy/.env for the first week: it logs what it would refuse and refuses nothing. The guard says what to read after it.

Environment variables

deploy/.env.example documents every variable. The ones you set:

VariablePurpose
PUBLIC_URLThe public address of the instance, with no trailing slash. Used for sign-in callbacks and webhooks.
SESSION_SECRETRandom secret that signs the session cookies. install.sh generates one.
WEB_PORTThe private port the app listens on (default 8080). Not your site's public port: your proxy forwards 443 to http://127.0.0.1:8080. Never set it to 80 or 443 behind a proxy.
WEB_BINDThe address that port is published on. Empty means every interface. When your proxy runs on the same server set 127.0.0.1, so the proxy is the only way in.
GITHUB_APP_ID, GITHUB_APP_SLUG, GITHUB_APP_CLIENT_ID, GITHUB_APP_CLIENT_SECRET, GITHUB_WEBHOOK_SECRETThe App's credentials, shown once after the one-click registration. Empty on the first start.
the private key fileNot a variable: put the .pem at deploy/secrets/github-app.pem. Mounted read-only.
CLAUDE_CODE_OAUTH_TOKEN, ANTHROPIC_API_KEY or ANTHROPIC_BASE_URLHow the agents get a model. Set one. The agents run inside the worker container, so the claude login on your server is not visible to them. Without one, steps fail with "Not logged in".
SHELF_MODEL, SHELF_MAX_TURNS, SHELF_MAX_BUDGET_USDOptional: force a model, and bound what one step may use.
SHELF_WARDEN_PROFILE, SHELF_WARDENThe guard's profile (shelf by default, strict, observe), and whether it is on. See the guard.
TEMPORAL_ADDRESS, TEMPORAL_NAMESPACEUse your own Temporal instead of the bundled one (and delete that service).

Local or server mode

Set mode in deploy/config/shelf.toml. In server mode GitHub's webhooks wake waiting work and a slow poll is a safety net. In local mode there is no public address, so waiting work looks at GitHub on a durable timer that slows down while nothing happens. The mode is read at start only.

Update

git pull
sh deploy/install.sh

The same script rebuilds and replaces the running containers.
