Architecture

Hexagonal layers around a pure functional core.

Overview

A person signs in with GitHub (one GitHub App), starts work from the web interface, and the web service asks Temporal to run a WorkItem workflow. The worker runs that workflow and its activities: a fresh git clone per step, the agent role of the phase on the Claude Agent SDK, the project's checks, and the pull request on GitHub. The workflow decides nothing itself: it feeds events to the pure decide function of the domain and executes the commands it returns. People answer at gates in the interface or with /shelf comments; GitHub webhooks (server mode) or a slowing durable poll (local mode) tell waiting work what happened.

ServiceDoes
webSign-in, the board, the start form, decisions, webhooks, the admin page.
workerThe WorkItem workflow and its activities; runs the agents under Warden.
temporalDurable workflows (bundled, or your own cluster).

Layers

LayerHolds
domainThe pipeline, the work-item state machine, policy, roles, commands and access rules. Pure: the standard library only, no I/O.
portsThe protocols the application needs from the outside world.
applicationUse cases that orchestrate the domain through ports: sign in, start work, decide, the board, run a step.
adaptersTemporal, the GitHub App, git, the Claude Agent SDK, configuration, the catalog, the web interface. Adapters never import each other.
entrypointsThe composition roots shelf-web and shelf-worker, which wire everything.

Dependencies point inward only, enforced by an import linter in CI.

The pure decider, the thin workflow

All the rules live in one function:

decide(course, state, event) -> Transition(state, commands)

Given the course (the phases this work runs, shaped by its entry point and policy), the current state and an event (a person decided, a check finished, a round ended), it returns the next state and the commands for the outside world. The Temporal workflow receives events, calls decide and carries out the commands. Because the function is pure it is tested with property-based tests, and a workflow change must replay existing histories (a replay test runs on a real Temporal server).

Warden

warden/ is a separate Rust component with its own binary, tests and releases. Python reaches it only through the warden binary, wired into each agent's hooks. See the guard and decision record 0014.

Stack

Python 3.13 with strict typing, Temporal for durability, the Claude Agent SDK for agents, FastAPI and a Python-only web interface, Rust for the guard, property-based tests, Apache-2.0. Behaviour is specified in openspec/specs; the reasons for the big choices are in the decision records, and Engineering has the rest.
