Concepts

The few ideas the whole system is built from.

The pipeline

Software work moves through need, spec, design, plan, implement, verify, code review and pull request. Each step has a producer (an agent) and, where it makes sense, a reviewer.

Entry points

Work does not have to start at the beginning. You can enter at any step, for example with a written spec, or hand over an existing pull request and ask only for a review.

Gates

At a gate the work stops and waits for a person. The decisions are a closed list: approve, request changes, resume, reject and abort. They can come from the web UI or from the pull request.

Loops and rounds

When a reviewer asks for changes, or checks fail, the producer tries again. Each attempt is a round, and every loop has a fixed maximum. When the limit is reached the work escalates to a person instead of continuing.

Different models for producing and reviewing

Reviewers use a different model than producers, so a review is not the same model agreeing with itself.

Roles

There is no user database. An operator file, shelf.toml, lists the organisations and users allowed in and the admins. Each repository can then grant per-repository roles in .shelf/config.toml. See Configuration.

Durable work items

Each work item is a Temporal workflow. It keeps its place across restarts, and waiting for a person costs nothing.
