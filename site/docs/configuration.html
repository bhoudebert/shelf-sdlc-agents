Configuration

Two files: one for the operator, one for each repository.

Early development. The two files below are parsed and validated by the code today. The web interface and deployment that read them are still being built.

shelf.toml (operator)

Kept by whoever runs the instance and mounted into the container. It decides who may sign in, and how waiting work learns what happened on GitHub. An empty file is a closed instance in local mode: nobody can sign in until it names someone. Unknown keys are refused, so a typo is an error, not silence.

# shelf.toml
mode = "server"            # "local": no public address, poll GitHub often
                           # "server": webhooks wake the work, the poll is a slow safety net

[access]
orgs   = ["acme"]          # members of these organisations may sign in
users  = ["alice", "bob"]  # these users may sign in
admins = ["alice"]         # may sign in, and may decide at any gate

Access is closed by default. A person signs in only if they are in users or admins, or belong to an organisation in orgs; everyone else is refused. With all three empty nobody can sign in, you included, so name yourself first. The same list governs /shelf commands written on a pull request: someone outside it is ignored, whatever their rights on the repository.

.shelf/config.toml (per repository)

Lives in the repository, so changes to who may do what are reviewed like any other change. Every key is optional.

# .shelf/config.toml
entries = ["need", "spec", "design", "plan", "implement", "pull_request_review", "pull_request_work"]
base_branch = "main"
checks = ["make test"]      # what the verify step runs

[policy]
max_rounds = 3             # how many times a loop may send work back before a person is asked
spec_approval = true       # a person approves the spec before the design starts
design_review = true       # a reviewer checks the design before the plan

[roles]                    # without roles, any signed-in person may decide
product_owner = ["alice"]  # decides at the spec gate
architect     = ["bob"]
tech_lead     = ["bob", "carol"]
developer     = ["dan"]

Roles limit who may decide only once you set them. The spec gate belongs to product_owner, the design review to architect and tech_lead, and the pull request to tech_lead and developer. Administrators may always decide.
