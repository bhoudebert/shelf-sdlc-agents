The board

Work is grouped by what it asks of you: Needs you first (gates, failures to resume, pull requests waiting for the merge), then Running, then Finished. Each row shows the request, the repository, who asked, a status chip, a ten-cell strip of the pipeline and the phase. The board updates live. Administrators see every repository's work; everyone else sees what is on repositories they can open.

On the pull request

The pull request opens as a draft after the first step, carries one shelf: stage label, and has one progress comment that is updated after every step. Whenever the work waits for a person, a comment says why and how to answer. Answer there if you like:

/shelf approve
/shelf changes the points should expire after 12 months
/shelf resume [note]
/shelf reject
/shelf abort

The first line of a comment must start with /shelf and one of those words. Only people the instance's list allows (and, where roles are set, with the right role) count. The factory ignores its own comments.

Have a pull request reviewed

Choose Review my pull request and give its number. The work enters at code review, read only: nothing is changed on the pull request, and the review is posted on it. The pull request must exist in the repository.

Have an agent work on my pull request

Choose Work on my pull request, give its number and say what to do (rebase, fix, verify). The agents change its branch, wait for its CI and review the result. They may force-push that branch when a rebase needs it, only if nobody pushed to it meanwhile. It must be a pull request that can be changed.
