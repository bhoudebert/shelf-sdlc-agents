Security model

What the system is designed to guarantee, and where the limits are.

Installation tokens

Access to a repository uses short-lived GitHub App installation tokens. A token is minted for each step and never stored.

Agents touch only their clone

Each step runs in a fresh clone of the repository. An agent works inside that clone and has no access to other repositories or to the host.

Access list

There is no user database. Who may sign in comes from the operator's shelf.toml, and per-repository roles from .shelf/config.toml. Someone not on the list cannot start or decide work.

A closed list of decisions

Decisions at gates (approve, request changes, resume, reject, abort) are a closed list of commands taken from the UI or the pull request. A model never interprets them, so text written by or into a model cannot approve its own work.

Bounded loops

Every retry loop has a maximum number of rounds and then hands over to a person.

Reporting a vulnerability

Follow the security policy in the repository. The project is in early development and has not had an external audit.
