Security model

What the system is designed to guarantee, and where the limits are.

Installation tokens

Access to a repository uses short-lived GitHub App installation tokens. A token is minted for each step and never stored or logged. Only the implementer gets one in its environment (valid one hour); it covers every repository the App is installed on, which Limits lists as a weakness with a plan.

Closed by default

There is no user database. Who may sign in comes from the operator's shelf.toml; with the lists empty nobody can. Repositories follow the same list, so installing the App on someone else's account does not open your instance. Per-repository roles come from .shelf/config.toml. Someone not on the list cannot start or decide work, and their /shelf comments are ignored.

A guard around every agent

Every agent runs under Warden, which checks each command, file access and fetch before it runs, keeps secrets and personal data off the model and logs every decision in a hash chain. The operator's policy is locked: a repository can only tighten it. It reads text and is not a sandbox. The guard shows it working; Limits says what it does not cover.

Each step has its own clone

Each step runs in a fresh clone, and the worker does the commit and the push. Agents are not yet isolated from the worker or from each other, so a clone is a convention and not a wall. A sandbox (Claude Code's) and a site allowlist (SHELF_ALLOWED_DOMAINS adds to it) limit what commands can reach. Limits says what that means and how it will be closed.

A closed list of decisions

Decisions at gates (approve, request changes, resume, reject, abort) are a closed list of commands taken from the web page or the pull request, matched by word. A model never interprets them, so text written by or into a model cannot approve its own work. Agents never merge.

Bounded loops

Every retry loop has a maximum number of rounds and then hands over to a person.

The web interface

Sessions are signed cookies with no user table. State-changing requests from other origins are refused. The interface makes no request to a third party and loads no script from one. The GitHub webhook is verified with its secret before anything is read.

Reporting a vulnerability

Follow the security policy. The project is in early development and has had no external audit; statements about the code come from reading it, not from attacking it.
